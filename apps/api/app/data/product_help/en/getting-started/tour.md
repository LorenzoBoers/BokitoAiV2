# Product tour

After you create a workspace, owners finish a short **first-run wizard** (`/onboarding`) — **About you**, **Languages**, **Notifications**, **Autonomy**, **Your agent**, optional **Channel** — before this tour. **Your agent** creates the workspace lead and uses the same living bot mark as the rest of the platform: shape, color, and motion. It does not rename Bokito, the in-app helper. Invited members only set personal language and notifications. The rail tour does not auto-start until that wizard is done. Finishing the wizard opens New conversation with the agent you just created, and that agent starts the setup chat.

## After the tour

1. End the tour with **Start the setup chat**, **Open Communication**, or **I will explore on my own**.
2. The app opens New conversation with that agent. They ask if the name is right, then about the company and how work should run.
3. Proposals wait in Govern. A daily check-in starts only if you say yes in that conversation.

Bokito has one sidebar. Pinned items sit above three groups: Work, AI and Organization. Use the command palette (`Ctrl+K` or `Cmd+K`) to jump without hunting the rail.

## Daily loop at the top

![Sidebar with the daily loop](/api/docs/assets/tour/sidebar.png)
*New conversation and Inbox sit above the grouped sections.*

- **New conversation** — opens `/new` to start a conversation.
- **Inbox** — the conversations, and the contacts behind them. Pinned above **Work**, not inside that section. See [Communication](/docs/inbox/communication) and [Contacts](/docs/inbox/contacts).
- **Today** — the morning scan of open work, decisions and usage, first inside Inbox. See [Today](/docs/getting-started/cockpit). Under Profile you can set your start page to **New conversation** (default), **Inbox**, **Agenda** or **Today**.

## Work and AI

- **Folders** — a tag with a place: conversations, boards and docs under one path. See [Folders](/docs/ai/folders).
- **Flows** — ticket pipelines, each titled with its label. See [Flows](/docs/ai/flows).
- **Agenda** — when agents wake; lives under **Work**. See [Agenda](/docs/ai/agenda).
- **Agents** — hire and brief. See [Agents](/docs/ai/agents).
- **Knowledge** — docs, skills and memory; equal sibling next to Agents. See [Knowledge](/docs/ai/knowledge).
- **Grid** — the organization map: departments, people, agents and links. See [Workforce](/docs/getting-started/team).

## Organization: people, tools and config

At the bottom of the rail, **Organization** groups the workspace itself:

- **Workforce** — the people, the agents and the departments they form, with who is available now. See [Workforce](/docs/getting-started/team).
- **Connections** — its own item in the main menu, above **Settings**. Modules, partner logins, tools and AI tools on one page (`/connections`). Installed modules (for example **Accounting**) do not add their own rail tabs. See [Connections](/docs/integrations/integrations).
- **Settings** — grouped as Personal (**Profile & security**, **Notifications**, **My assistant**), Workspace (**General**, **Branding**), Communication (**Channels**, **Autonomy**, **Labels**), AI and control (**Govern**, **Models**, **Data & privacy**) and Advanced (**Developers**). **Bin** and **Support** sit at the bottom of the settings sidebar. **Support** opens the setup guide, product tour, docs, API reference and contact options. Website chat is a channel row under **Channels**, not its own settings item. See [Labels and tickets](/docs/ai/categories).

Owners and admins use Organization most; members mainly open Workforce. See the [setup guide](/docs/getting-started/setup-guide).

Personal screens — **Profile** and **Notifications** — are yours, not workspace docs. On Profile, set **First name** and **Last name** (used in greetings and email signatures), choose **Start page** as **New conversation** (default), **Inbox**, **Agenda** or **Today**, **Appearance** as **Light**, **Dark** or **System**, and optionally a personal **Email signature** as the fallback when a mailbox uses each person's signature or has no shared template. Shared mailbox signatures live under **Settings** → **Channels**.

## Use the command palette

1. Press `Ctrl+K` (Windows) or `Cmd+K` (Mac) from any signed-in page.
2. Type to jump. Results group under **Recent**, **Go to**, **Actions**, **Sessions**, **Threads**, **Contacts**, **Messages queues**, **Knowledge** and **Settings**.
3. With an empty query, **Actions** also offers **New conversation**, **Talk to an agent**, **Open agent**, **Open flow**, **Open folder**, **Open Knowledge**, **Open Agenda**, **New flow**, **Invite a teammate**, **Open my profile**, **Open notifications**, **New email**, **New contact**, **New agent**, **New folder**, **Connect mailbox**, **Open setup guide**, **Open help (Bokito)** and **Open support**. **Open folder** and **New folder** open a folder.
4. Settings pages appear after you type. You can **Switch to light mode** or **Switch to dark mode** from the palette too.

Communication search in the thread list searches conversations. The palette is for jumping, not for inbox filters.

## Ask Bokito

1. Choose **Help** in the top bar (next to **Setup** while onboarding is incomplete), or the Bokito button in the bottom-right on pages where the launcher is shown. On Communication with an open thread, and on New conversation, the corner launcher stays hidden so it does not cover Send; use the top bar **Help** button to force the panel open.
2. Type your question. Bokito knows which page you are viewing, so "what does this status mean?" works without explaining where you are.
3. The conversation runs with your own permissions, and Bokito hands real work to the workspace agents. See [Bokito, your assistant](/docs/getting-started/assistant).

## Two other shortcuts

The account menu offers **Profile**, **Settings**, **Workspaces** and **Support**. The footer repeats the support line `environment · tenant-slug · Live · 1.2.01`. **Support** (`/settings/help`) links to the setup guide, product tour, `/docs`, `/docs/api` and contact options. The public site is `/docs` (no login). In-app Learn remains at `/learn` for page banners.
