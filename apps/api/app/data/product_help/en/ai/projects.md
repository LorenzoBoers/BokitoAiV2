# How Projects works

A project is work that spans days. Open **Projects** when a goal should have a home instead of living only in chat.

## Create or open a project

![Projects list](/api/docs/assets/projects/project.png)
*Each card shows the lead agent and budget.*

1. Open **Projects**. Choose **New project** and name the goal. The URL slug is generated for you; open **Advanced: URL slug** only if you need to change it.
2. Read the card: lead agent, repo status, remaining budget. Search by name or lead when the list grows.
3. Open it. The **Who runs this** card shows the lead. Use **Change lead** to pick another agent or create one. Members can read a project; they cannot delete it or edit the name.

Status on a card can be working, idle, paused, or blocked (needs you).

## Keep talking in Communication

1. From the project, choose **Open communication**.
2. You land in [Communication](/docs/inbox/communication) filtered to that project. The list shows a banner you can clear.
3. Agents and humans keep talking there. The project is the spine.

## Cap spend

1. Open the project.
2. Set daily and hourly token budgets so one goal cannot consume the whole workspace cap.
3. When a project hits its cap, the card shows **Token budget reached**. Workspace caps still live on Cockpit **Usage**.

## Connect a repository

1. On create or from the project, choose **I use GitHub** to link a repo you already have, or **Set it up for me** for a managed repo (no GitHub account). **Set it up for me** can still show **Coming soon**. If GitHub is not connected yet, **Open Integrations** takes you there first.
2. For GitHub, choose **Connect with GitHub**, pick **Select a repository**, then **Link repository**. Status moves from **Indexing repo** to **Repo ready**.
3. Agents then search that repo in context of the project. No repo is fine for non-code work. Marketplace GitHub tools are separate from this project index.
