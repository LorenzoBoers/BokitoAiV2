# How Knowledge works

Knowledge is what agents read on every run. Open **Knowledge** to add a document, not to write a private wiki.

## Pick the right kind

![Knowledge page](/api/docs/assets/knowledge/add-doc.png)
*Add the documents agents should answer from.*

The sidebar groups kinds:

- **Voice** — how you sound. Tone, phrases to use or avoid.
- **Memory** — long-term facts the workspace should remember. Agents update this as they learn.
- **Skills** — procedures: how to refund, how to escalate, how to book.
- **Docs** — reference pages (pricing, policy, product facts). Only this kind can be published to a help center.
- **Check-ins** — recurring heartbeat checklists. Agents write here when a scheduled check finds something.
- **Daily notes** — short logs agents keep. You read them; you rarely author them.

Memory, check-ins and daily notes are AI-maintained. Edit them when a fact is wrong; do not treat them as a second wiki.

## Add a document

1. Open **Knowledge**. An empty library offers **Create first document** and a drop zone for a PDF or Word file. Use **Search knowledge** (Enter or **Search**) when the list is long, or **Clear search** to browse again. Kind chips filter Voice, Memory, Skills, Docs, Check-ins and Daily notes.
2. Choose **New document**, type a title (the path is generated), then **Add**. Or use **Upload a document (PDF, Word, text)**.
3. **Save** or press Ctrl/Cmd+S. Leaving with unsaved edits asks you to confirm. Click the document path to copy it. Memory, Check-ins and Daily notes show **Kept up to date by agents**. **Publish** asks if the article should appear on the public help site. **Delete document** removes a page you no longer want.

## Ground a draft

1. Add the pages your team already uses: pricing, policies, product facts.
2. Open a thread in [Communication](/docs/inbox/communication).
3. Drafts improve once a handful of documents exist. Inbox AI still follows [Inbox AI](/docs/inbox/inbox-ai); Knowledge only grounds the wording.

## Publish for customers

1. Open a document of kind **Docs**.
2. Choose **Publish** (**Publish on the public help center**). The row shows a **Published** badge. That article goes to your [help center](/docs/inbox/help-centers), not to Bokito product help.
3. Use **Remove from the public help center** when it should leave the public site. **View on help center** opens the live page.

## What to do next

Brief an [agent](/docs/ai/agents) after the first documents are in. Turn on Help on the [widget](/docs/inbox/widget) if visitors should see those articles.
